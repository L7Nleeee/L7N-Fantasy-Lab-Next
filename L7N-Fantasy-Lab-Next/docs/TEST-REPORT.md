## 3. GitHub Actions
- `.github/workflows/data-update.yml`、`pages.yml` 已通過 YAML 語法解析。
- **沒有在 GitHub 上執行過**。我把 workflow 中的 shell 步驟（建立 `data` 孤立分支、worktree、執行管線、commit/push、失敗時 job 變紅）在**本機的假遠端 git 倉庫**上逐字模擬了三輪：
  1. 第一輪（尚無 data 分支）→ 建立分支並推送，結束碼 0；
  2. 第二輪（資料不變）→ 管線回報 `unchanged`；（只有 `status.json` 的檢查時間會變，所以每天仍會有一個小 commit）；
  3. 第三輪（來源有壞列）→ 管線結束碼 1；**status.json 被提交，manifest.json 仍指向舊版本**；job 會在提交後顯示失敗。
- 這只證明 shell 邏輯與管線行為，**不等於**證明 GitHub 權限、runner 環境、NBA 是否擋 GitHub IP。
